# YOLO 检测器：理论

本文讲清 `YoloDetector` 背后的原理：YOLO 输出张量长什么样、letterbox
的数学、NMS 在干什么。读完你能手推从原始张量到检测框的全过程。

## 1. YOLO 是什么

YOLO（You Only Look Once）是一阶段目标检测器：单次前向传播同时输出
目标位置与类别，无需候选区域。YOLOv8/v11 采用 anchor-free 设计——
不再预设锚框，直接回归目标中心与宽高。

本项目使用 YOLO11n（nano，~11MB），通过 `cv2.dnn` 加载 ONNX 模型，
不依赖 ultralytics 包。

## 2. 输出张量：(1, 84, 8400)

一次前向传播输出形状为 `(1, 84, 8400)`：

- `8400`：候选框总数。来自三尺度特征图：
  80×80 + 40×40 + 20×20 = 6400 + 1600 + 400 = 8400（输入 640×640 时）。
- `84`：每个候选框的 4 个坐标（cx, cy, w, h，单位为 640 像素空间）
  + 80 个 COCO 类别的置信度分数。

即：模型对 8400 个位置各提一个框，并给 80 类分别打分。

## 3. Letterbox：为什么不能直接 resize

直接把 640×480 的图压成 640×640 会破坏宽高比，目标被压扁，
检测框不再对应真实形状。Letterbox 的做法：

```
scale = min(640/w, 640/h)          # 等比缩放
pad   = (640 - w*scale) // 2       # 灰边居中填充
```

坐标还原时逆运算：`x_orig = (x_640 - pad_w) / scale`。
`_letterbox()` 返回的 `(scale, pad_w, pad_h)` 正是为此准备的。

## 4. 后处理三步

1. **类别决策**：每行取 80 类分数的最大值作为该框的置信度，
   `argmax` 为类别。低于 `conf_thresh` 的直接丢弃。
2. **类别过滤**（可选）：`classes=["person"]` 时只保留指定类别，
   跟踪器从此只看人。
3. **NMS（非极大值抑制）**：同一目标会被多个候选框命中。
   按分数排序，逐个压制与其 IoU 超过 `nms_thresh` 的框，
   只留每簇中分数最高的。`cv2.dnn.NMSBoxes` 实现。

## 5. 与 MOG2 的取舍（理论层面）

| 维度 | MOG2（运动检测） | YOLO（深度检测） |
|---|---|---|
| 原理 | 背景建模，找"动了的像素" | 卷积网络，找"像某类物体的区域" |
| 摄像头移动 | 不可用（背景模型崩坏） | 可用 |
| 静止目标 | 会被学进背景而消失 | 正常检测 |
| 语义 | 无（只知道"有东西在动"） | 有（人/车/狗……80 类） |
| 代价 | ~5ms/帧，零权重 | ~230ms/帧（CPU），~11MB 权重 |
| 失效模式 | 光照突变、抖动 | 训练域外目标（如合成白方块） |

两者输出统一为 `[x1, y1, x2, y2, score]`，跟踪器无感切换——
这正是 `Detector` 接口存在的意义。量化对比见
[comparison.md](comparison.md)。
